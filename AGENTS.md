# AGENTS.md

Guidance for AI coding agents (Codex, Claude, Copilot Workspace, etc.) working in
the **AlgebraicSolving.jl** repository.

## Project overview

AlgebraicSolving.jl is a Julia package for solving systems of polynomial
equations and related computer algebra tasks (Gröbner bases, elimination,
real solving, etc.). It builds on top of fast C library `msolve`,
https://github.com/algebraic-solving/msolve,
via Julia's `ccall`/`Libdl` FFI, and is designed to interoperate with the
OSCAR computer algebra system. Correctness and numerical/algebraic soundness
are paramount — this is mathematical software used in research.

Key directories (verify against the current tree before editing, structure
may evolve):

- `src/` — Julia source code (core algorithms, wrappers around C libraries,
  data types for polynomial rings, ideals, groebner bases, etc.)
- `test/` — `Test.jl`-based unit and regression tests
- `docs/` — Documentation source (built with `Documenter.jl` if present)
- `deps/` or `Artifacts.toml` — build scripts / binary dependency management
  for linked C libraries
- `Project.toml` / `Manifest.toml` — package metadata and dependencies

## Setup

```bash
# From the repo root
julia --project=. -e 'using Pkg; Pkg.instantiate()'
```

If the package wraps a compiled C library, ensure the corresponding
artifact/binary dependency downloads or builds successfully before running
any code that calls into it. Do not hand-edit `Manifest.toml`; regenerate it
via `Pkg.instantiate()` / `Pkg.resolve()` when dependencies change.

## Building

```bash
julia --project=. -e 'using Pkg; Pkg.build("AlgebraicSolving")'
```

Run this whenever native dependencies or build scripts change.

## Testing

Always run the test suite before proposing a change as complete:

```bash
julia --project=. -e 'using Pkg; Pkg.test("AlgebraicSolving")'
```

or, for iterative development:

```bash
julia --project=test test/runtests.jl
```

- Add or update tests in `test/` for any new functionality or bug fix.
- Prefer small, focused test cases using standard polynomial rings over
  `QQ`, `GF(p)`, etc., mirroring existing test style.
- Do not weaken or delete existing tests to make a change pass; fix the
  underlying issue instead.

## Code style

- Follow standard Julia community style: 4-space indentation, no tabs.
- Use `snake_case` for functions/variables and `CamelCase` for types/modules,
  consistent with existing code.
- Exported functions should have docstrings (`"""..."""`) with a short
  description, arguments, and an example if practical (Julia doctest style),
  matching conventions already used in `src/`.
- Keep public API changes backward compatible unless explicitly requested;
  AlgebraicSolving.jl is used downstream by other packages (e.g. OSCAR).
- When wrapping C functions, keep `ccall` signatures and memory-ownership
  semantics carefully documented — mistakes here cause segfaults or memory
  corruption, not just wrong answers.
- Avoid introducing new external dependencies without strong justification.

## Documentation

If `docs/` exists, update relevant `.md` files or docstrings when public
behavior changes. Build docs locally if feasible:

```bash
julia --project=docs -e 'using Pkg; Pkg.instantiate(); include("docs/make.jl")'
```

## Pull request / commit guidelines

- Keep commits focused and descriptive; explain *why*, not just *what*.
- Reference related issues where applicable.
- Run the full test suite (`Pkg.test`) locally before opening a PR and
  include the result summary in the PR description.
- **Any commit or pull request authored or substantially generated by an AI
  agent must include a co-author trailer identifying the specific AI tool
  used**, for example:

  ```
  Co-authored-by: <AI-Agent-Name> <ai-agent@users.noreply.github.com>
  ```

  Use the actual tool/model name in place of `<AI-Agent-Name>` (e.g.
  `OpenAI Codex`, `Claude`, `GitHub Copilot`), and apply this to every
  commit message trailer as well as noting it explicitly in the PR
  description (e.g. "This PR was generated with assistance from
  <AI-Agent-Name>").
- Do not remove or alter existing co-authorship/attribution trailers from
  human contributors.

## Safety / correctness notes for agents

- This package implements mathematically sensitive algorithms (Gröbner
  bases, real root isolation/counting, elimination). Do not "simplify" or
  "optimize" algorithmic code without verifying correctness against the
  test suite and, ideally, known mathematical examples.
- Be cautious modifying FFI/`ccall` boundaries to C libraries; validate with
  tests that exercise the modified code paths, including edge cases (zero
  ideals, non-radical ideals, different characteristics/fields).
- If unsure whether a change preserves mathematical correctness, add a
  regression test with a known expected result rather than assuming.
